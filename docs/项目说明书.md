## 1. 一句话概述

在 **STM32MP157(ARM Cortex-A7,Linux)** 平台上,为 **Invensense MPU-6050 /
6500 / 9250 六轴 IMU(加速度计 + 陀螺仪 + 温度)** 编写的一个**挂在 Linux IIO
(Industrial I/O)子系统下、按 mainline vendor 驱动标准组织的字符/内核设备驱动**。

它刻意做到"网上教程止步之后"的工程完成度,用作嵌入式 Linux 驱动方向的
**求职作品集**与技术深聊材料。

---

## 2. 项目背景与动机

- **痛点**:网络上的 MPU-6050 例程 99% 停在"i2c 读 14 字节寄存器、printf 打印",
  既不挂内核框架,也没有功耗、并发、事件、测试、文档等真实工程要素——面试时讲不深,
  和别人雷同,无法证明工程能力。
- **目标**:做一个**看起来像公司里真实交付的 BSP 驱动**的项目。芯片虽普通,但把
  驱动的工程完成度拉到量产水准,差异化就出来了。
- **框架选型**:选 **IIO** 而非直接裸字符设备。IIO 与相机领域的 V4L2 同源——都是
  "统一设备模型 + 标准用户空间 ABI + 可选缓冲/硬件触发数据流"的框架思想,但复杂度
  友好;且手机 SoC 的 sensor 子系统正是 IIO,方向对口。

## 3. 技术栈

### 3.1 内核侧(驱动本体)
| 类别 | 采用的技术 / 子系统 | 作用 |
|------|--------------------|------|
| 目标框架 | Linux **IIO** 子系统 | 通道模型、sysfs/字符设备 ABI、buffer、trigger、events |
| 寄存器抽象 | **regmap**(regmap-i2c) | 统一读写、缓存、debugfs dump、总线无关 |
| 总线 | **I2C**(i2c_driver) | 与 MPU-6050 通信;预留 SPI 前端扩展 |
| 设备匹配 | **Device Tree** + OF match | `compatible = "invensense,mpu6050"` |
| 数据搬运 | **triggered buffer**(kfifo)+ 硬件 FIFO 水位 | 中断驱动的批量采集 |
| 中断 | GPIO **threaded IRQ** + `iio_trigger` | DRDY 数据就绪 / FIFO 溢出 / 运动检测 |
| 电源管理 | **runtime PM** + system suspend/resume | autosuspend 到 sleep,省电 |
| 事件 | **IIO events** | wake-on-motion 阈值中断 |
| 资源管理 | **devm_** 全托管 | 无手写 remove,错误路径用 `dev_err_probe` |
| 并发 | mutex + `claim_direct_mode` | 配置写 / 数据读 / 缓冲互斥 |

### 3.2 工程配套
| 类别 | 技术 |
|------|------|
| 构建 | Kbuild(双用途 Makefile:外部模块 + 交叉编译)、Kconfig |
| 交叉编译 | `arm-linux-gnueabihf-` 工具链,在 Ubuntu 上 build |
| 文档 | DT binding(YAML,可过 `dt_binding_check`)、sysfs ABI 文档、架构说明 |
| CI | **GitHub Actions**:拉取 Linux 6.1/6.6 源码 → 配 IIO 依赖 → 编译模块;checkpatch 风格检查;userspace 构建 |
| 代码规范 | Linux kernel coding style、SPDX 许可标识、checkpatch |
| 验证 | C 测试程序(sysfs 换算校验重力、缓冲流式读取)、上板冒烟脚本 |
| 版本/许可 | Git、GPL-2.0-only、CHANGELOG、CONTRIBUTING |

### 3.3 硬件与联调环境
- 板卡:**100ASK STM32MP157 PRO**(Cortex-A7 + M4,跑完整 Linux)
- 传感器:**MPU-6050**(I2C 地址 0x68,带 FIFO 与 DRDY/motion 中断)
- 联调:板 ↔ Ubuntu VM 网口直连(TFTP/NFS 加载模块),串口 CH340 @115200 看 dmesg

## 4. 架构总览

```
        用户空间: iio_info / libiio / sysfs / /dev/iio:deviceN
                          │  统一 IIO ABI
                    IIO core(内核)
                          │  iio_info 回调
  mpu6050-core.ko ────────┤  设备模型·通道·read/write_raw·PM·buffer·events·selftest
                          │  regmap(寄存器抽象)
  mpu6050-i2c.ko  ────────┤  I2C 前端(模块入口·变体匹配)
                          │  I2C 总线
                     MPU-6050 硬件
```

**两个模块拆分**(仿 mainline `inv_mpu6050`):总线无关逻辑在 `core`,总线相关在
`i2c`;将来加 SPI 只需再写一个 `spi` 前端调用同一 `mpu6050_core_probe()`。

**两条数据通路**:
1. **sysfs 单次**(direct mode):`cat in_accel_x_raw` → regmap 读 → 换算。
2. **缓冲流式**:选通道 → `buffer/enable` → DRDY/FIFO 中断 → pollfunc 批量读 →
   `iio_push_to_buffers_with_timestamp` → 用户 `read(/dev/iio:deviceN)`。

## 5. 功能清单

- 多芯片变体(6050/6500/9250)`chip_info` 能力表抽象
- accel xyz / gyro xyz / temp 通道 + 硬件时间戳
- 可配置量程与采样率,`*_scale_available` / `sampling_frequency_available`
- 触发缓冲:DRDY 数据就绪触发 + 软件(sysfs)触发
- 硬件 FIFO 水位批量搬运(`hwfifo_watermark`),降中断/唤醒
- 运动检测事件(wake-on-motion 阈值中断)
- runtime PM autosuspend + system suspend/resume
- factory self-test(sysfs 读触发,内核纯整数响应窗口判定)
- 完整 DT binding / sysfs ABI / 架构文档 / CI / 测试程序

## 6. 应用场景

这类 IMU 驱动是**移动与嵌入式设备的基础能力**,真实落地场景包括:

| 场景 | 用到的本项目能力 |
|------|------------------|
| **手机 / 平板 屏幕旋转、计步、姿态** | accel/gyro 数据流 + 低功耗 ODR |
| **可穿戴 / TWS 佩戴与敲击检测** | 运动检测事件、wake-on-motion(主机休眠靠中断唤醒) |
| **无人机 / 平衡车 / 机器人 姿态解算** | 高采样率 gyro+accel、DRDY 硬件触发、精确时间戳 |
| **AR/VR 头显 头部追踪** | 高吞吐缓冲流 + FIFO 水位降 CPU 负载 |
| **IoT 设备 跌落/震动/防拆告警** | 运动阈值事件、超低功耗待机 |
| **工业设备 振动监测** | 连续缓冲采集 + libiio 上位机分析 |
| **always-on 传感中枢(sensor hub)** | FIFO 批量 + runtime PM,主 CPU 尽量休眠 |

其中 **FIFO 水位批量搬运 + runtime PM + wake-on-motion** 三点,正是手机 SoC
厂商(如高通)sensor 子系统最看重的**功耗工程**能力——这也是本项目区别于普通
例程、可在面试深聊的核心。

## 7. 如何使用(快速上手)

```bash
# 1) 交叉编译(在 Ubuntu 上,指向 MP157 内核源码)
cd drivers/iio/imu/mpu6050
make KDIR=/path/to/stm32mp157-kernel ARCH=arm CROSS_COMPILE=arm-linux-gnueabihf-
#    产出 mpu6050-core.ko / mpu6050-i2c.ko

# 2) 更新含 mpu6050@68 节点的 dtb(见 dt/ overlay),重启板子

# 3) 上板加载并验证
insmod mpu6050-core.ko && insmod mpu6050-i2c.ko
iio_info
sh test/smoke_test.sh
```

完整验证(缓冲流、FIFO 水位、事件、自检)见 [`README.md`](../README.md)。

## 9. 现状与路线图

**已完成(代码/文档/CI/测试,已推 main):** 见第 5 节功能清单。

**待推进(硬件 bring-up):** 按
[`docs/superpowers/plans/2026-09-22-mpu6050-iio.md`](superpowers/plans/2026-09-22-mpu6050-iio.md)
的 M1→M4 在真板逐步点亮并验证。

**已知边界(诚实说明):**
- 内核 API 基线 >= 5.15 / 6.1;STM32MP157 的 ST 5.4 BSP 需 README 里的兼容 shim。
- self-test 用整数响应窗口判定(内核禁浮点),datasheet 浮点 factory-trim 多项式
  作为后续扩展。
- FIFO 水位路径对整批帧共用一个时间戳,逐帧时间插值为可选增强。

**可扩展方向:** SPI 前端、mount-matrix 姿态旋转、DMP/磁力计(9250)、逐帧时间戳
插值、完整 factory-trim 自检。
