MPU-6050 驱动开发 · 命令速查卡

虚拟机(编译/部署)+ STM32MP157 开发板(加载/验证)· NFS+TFTP
核心原则:只改驱动代码 → 不用动设备树、不用重编 dtb、连板子都不用重启(NFS 实时,板子上 rmmod 旧 + insmod 新即可)。只有改了设备树(dts)才需要重编 dtb + 板子重启。

A　虚拟机终端(每次改完驱动代码)

cd ~/linux/Linux_Drivers/04_mpu6050_driver

# 交叉编译出 ARM 的 .ko(KERNELDIR 指板子内核)
make KERNELDIR=/home/yyf/linux/atk-mp1/linux/my_linux/linux-5.4.31

file mpu6050_iio.ko            # 确认输出含 "ARM"

# 部署到板子根文件系统(NFS 实时,拷完板子马上能看到)
cp mpu6050_iio.ko /home/yyf/linux/nfs/rootfs/

💡 省事:把 Makefile 里 KERNELDIR := /lib/modules/$(shell uname -r)/build 改成 KERNELDIR := /home/yyf/linux/atk-mp1/linux/my_linux/linux-5.4.31,以后直接 make 即交叉编译(就不再给 VM 自己编 x86 版)。

B　开发板终端(开机后)

# (板子没重启、驱动还在时)先卸载旧的;刚开机这步会提示没有,忽略即可
rmmod mpu6050_iio

insmod /mpu6050_iio.ko        # 加载新驱动
dmesg | tail                  # 期望:MPU-6050 detected! + registered

D=/sys/bus/iio/devices/iio:device0
cat $D/in_accel_x_raw $D/in_accel_y_raw $D/in_accel_z_raw
cat $D/in_anglvel_x_raw $D/in_anglvel_y_raw $D/in_anglvel_z_raw
cat $D/in_temp_raw

两种典型场景

① 只改驱动代码(最常见,板子不用重启)

VM :  make KERNELDIR=...   →   cp mpu6050_iio.ko .../nfs/rootfs/
板子:  rmmod mpu6050_iio   →   insmod /mpu6050_iio.ko   →   cat ...

② 改了设备树 dts(才需要重编 dtb + 板子重启)

VM(多做两步):
  cd /home/yyf/linux/atk-mp1/linux/my_linux/linux-5.4.31
  make stm32mp157d-atk.dtb
  cp arch/arm/boot/dts/stm32mp157d-atk.dtb /home/yyf/linux/tftpboot/
然后：板子重启(u-boot 重新从 tftp 载新 dtb) → insmod → cat

开机后一次性自检(可选)

ls /sys/bus/i2c/devices/      # 有 x-0068 = i2c4 和 mpu6050 节点都在(设备树生效)

常见坑

现象原因 / 处理
insmod: No such file or directory.ko 没拷到 rootfs(是 .../nfs/rootfs/,不是 .../nfs/)
read WHO_AM_I failed / 无 0x68接线:SCL/SDA 反、没供电、没共地;查线
改了代码但现象没变忘了重新 cp 到 rootfs,或板子上没 rmmod 旧的
file 显示 x86 不是 ARM没带 KERNELDIR=...linux-5.4.31,编成 VM 版了
改了 dts 不生效忘了 make ...dtb + 拷 tftpboot + 板子重启
